# Архитектура: за что отвечает каждый файл, как работают функции, как всё проверяется

[English](ARCHITECTURE.md) · [Português](ARCHITECTURE-PT.md) · [Українська](ARCHITECTURE-UK.md) · **Русский** · [Français](ARCHITECTURE-FR.md) · [Deutsch](ARCHITECTURE-DE.md)

## 1. Обзор

Программа — статическая страница без сборки и без зависимостей времени выполнения. Логика разделена на две части, которые **не обращаются к DOM** и работают и в браузере, и в Node (поэтому их легко тестировать), и тонкий слой интерфейса:

| Файл | Ответственность |
|---|---|
| `index.html` | разметка: дисплей, две клавиатуры (научная / простая), панели «Величины» и «Валюты», окна справки |
| `css/style.css` | оформление; светлая и тёмная тема через CSS-переменные, адаптивная вёрстка |
| `js/calc-engine.js` | `CalcEngine`: разбор и вычисление выражений, форматирование результата (без DOM) |
| `js/converters.js` | `Converters`: величины, валюты, загрузка курсов, данные для графика (без DOM) |
| `js/app.js` | интерфейс: состояние, обработка кнопок, клавиатура, режимы, рисование графика, справка |
| `docs/MANUAL.md` | руководство пользователя (на русском); его примеры выполняются в тестах |
| `test/` | автоматические тесты (раздел 5) |
| `variants/` | прежние варианты страницы, для истории; не развиваются и не тестируются |

Оба файла логики используют одну обёртку (UMD): `module.exports` в Node, глобальная переменная (`CalcEngine`, `Converters`) в браузере.

## 2. `js/calc-engine.js` — движок выражений

Публичный интерфейс: `evaluate(expr, { deg, ans })`, `parse`, `tokenize`, `formatNumber`, `formatValue`, `Matrix`, `CalcError`, `FUNCTIONS`, `FUNCTION_NAMES`, `CONSTANTS`.

### Конвейер

`evaluate` = `parse` → `evalNode` → устранение `-0`. Любая ошибка пользователя бросается как `CalcError` с понятным текстом; интерфейс показывает её и сохраняет выражение.

1. **`normalize`** заменяет символы отображения на ASCII: `× · ⋅` → `*`, `÷` → `/`, `− – —` → `-`, `π` → `pi`, `√` → `sqrt`.
2. **`tokenize`** делит текст на числа (`12`, `.5`, `1.5e3`), идентификаторы и операторы `+ - * / ^ ( ) [ ] , ! %`. Любой другой символ вызывает ошибку «Недопустимый символ».
3. **`parse`** — рекурсивный нисходящий разбор в AST. Приоритеты от низшего к высшему:
   `additive (+ -)` → `term (* /` и неявное умножение`)` → `unary (-, +)` → `power (^)` → `postfix (! %)` → `primary`.
   - Неявное умножение: `2pi`, `2(3+4)`, `3sin(30)`.
   - `^` правоассоциативна (`2^3^2 = 512`), а `-2^2 = -4` (унарный минус применяется после степени); `2^-3` работает, потому что показатель разбирается как унарное выражение.
   - Недостающие закрывающие скобки в конце ввода закрываются автоматически (`expect` в конце возвращает `null`).
   - Ограничения: 1000 символов, 100 уровней вложенности — защита от враждебного ввода.
   - Матрица записывается `[[1,2],[3,4]]`: список в скобках; список однострочных матриц одинаковой длины становится многострочной матрицей.
4. **`evalNode`** обходит AST. Основные правила:
   - **Проценты**: `50%` = 0.5; но в `200 + 10%` процент берётся *от левого операнда* (= 220); так же для `-`.
   - **Факториал** определён для целых 0…170.
   - **Константы** `pi`, `e` и `Ans` (последний результат, передаётся в `ctx.ans`).
   - **Вызов функции** сверяет число аргументов с реестром и вызывает реализацию.
5. **`check`** применяется к каждому результату: `NaN` → «Результат не определён», `Infinity` → «Переполнение».

### Реестр функций

`FUNCTIONS` сопоставляет имя и `{ n: [min, max], f(args, ctx, name) }`. 46 имён (без синонимов `trans`, `identity`, `fact`):

- тригонометрия и обратные: `sin cos tan asin acos atan atan2` (Deg/Rad через `ctx.deg`); гиперболические: `sinh cosh tanh asinh acosh atanh`
- экспонента, логарифмы, корни: `exp ln log10 log2 log sqrt cbrt hypot`
- округление и знак: `abs sign floor ceil trunc round`
- целые числа: `factorial ncr npr gcd lcm mod`
- статистика (принимает список или матрицу): `sum mean median min max std stdp`
- матрицы: `det inv transpose trace eye size`

Помощники: `ew(f)` применяет функцию одного числа поэлементно (к числу или к каждому элементу матрицы); `num`, `ints`, `flat` проверяют типы аргументов и бросают понятные ошибки.

### Точность вычислений

- `clean15` округляет результат до 15 значащих цифр и убирает шум плавающей точки (`0.1+0.2` даёт `0.3`).
- `cleanTrig` и особые случаи в `sin/cos/tan` возвращают точные значения для точных углов в градусах (`sin(180) = 0`, `cos(90) = 0`, `tan(90)` → ошибка).
- Матрицы: `matDet` — метод Гаусса с выбором главного элемента; `matInv` — Гаусса–Жордана; `pow` поддерживает целые степени квадратной матрицы (отрицательные — через обратную).

### Форматирование

`formatNumber(v, places)` — фиксированная запись с 0–14 знаками, незначащие нули убираются; экспоненциальная запись при `|v| ≥ 1e15` и для значений, которые при выбранной точности округлились бы до 0. `formatValue` выводит матрицы как `[[a, b], [c, d]]`.

## 3. `js/converters.js` — величины и валюты

### Величины

`UNITS` — таблица `категория → { label, units: { код: [название, коэффициент] } }`, где *коэффициент* — сколько базовых единиц в одной данной. Пересчёт: `значение × k(из) / k(в)`. 12 категорий: длина, масса, температура, объём, площадь, скорость, время, данные (десятичные и двоичные приставки), астрономические и три группы старинных русских мер (длина, площадь, вес).

- **Температура** — особая категория: значение переводится в кельвины и обратно (`toKelvin`, `fromKelvin`); значения ниже абсолютного нуля вызывают ошибку.
- `convertUnit` проверяет категорию, единицы и конечность числа. `formatUnitValue` выводит 10 значащих цифр, для очень больших/малых значений — экспоненциальную запись.

### Валюты

- `CURRENCIES` — 12 валют; `FALLBACK_RATES` — приблизительные курсы к USD для работы без сети.
- `fetchRatesFile` загружает `usd.min.json` открытого набора `currency-api`, пробуя по очереди два адреса (CDN jsDelivr и `pages.dev`); функция `fetch` передаётся параметром, поэтому тесты могут её подменить.
- `convertCurrency(amount, from, to, rates)` = `amount × rates[to] / rates[from]` (все курсы заданы к USD, поэтому подходит любая пара).
- График: `chartDates(days, today, maxPoints)` выбирает до 24 дат по возрастанию, последняя — сегодня; `fetchHistory` загружает их **параллельно**, складывает в объект-кэш и молча пропускает недоступные даты.
- `formatMoney` — разряды и 2…8 знаков в зависимости от величины.

## 4. `js/app.js` — интерфейс

- **Состояние** — один объект: выражение, прошлое выражение, `Ans`, Deg/Rad, Inv, страница Fn, история (до 50 записей, видны последние 3), текст ошибки.
- **`PAGES`** — шесть наборов Fn (Trig, Hyp, Mat, Stat, Comb, Rnd); у каждого 6 слотов, слот может задавать замену `inv` для включённого Inv.
- **`insert(val)`** — защита ввода. Не даёт набрать неверную последовательность: два оператора подряд (последний заменяет предыдущий), вторая точка в числе, ведущий `0` перед цифрой, закрывающая скобка без открывающей, `%`/`!` без операнда, запятая вне скобок. После `=` цифра начинает новое выражение, а оператор продолжает от `Ans`.
- **`backspace`** удаляет имя функции (`sin(`), `Ans` или `pi` целиком; **`calculate`** вызывает `CalcEngine.evaluate`, пишет историю, показывает сообщения `CalcError`, не теряя ввод.
- **Режимы** — Научный, Простой, Величины, Валюты; выражение общее у первых двух.
- **Клавиатура** — цифры и операторы, `Enter`/`=`, `Esc`/`Delete` (сброс), `Backspace`, `x` как умножение, `,` как десятичная точка (или разделитель аргументов внутри скобок). Игнорируется в полях ввода, при открытой справке и в других режимах.
- **Величины / Валюты** — заполняют списки из `Converters`, пересчитывают при каждом изменении; поля суммы и результата работают в обе стороны.
- **График курса** — рисуется на `<canvas>`; каждый запрос получает `token`, поэтому медленный устаревший ответ не затирает новый; подсказка при наведении/касании.
- **Сеть** — `fetchJson` добавляет тайм-аут 8 секунд; при сбое приложение переходит на офлайн-курсы и сообщает об этом.
- **Справка** — модальные окна: закрываются кнопкой, кликом вне окна или `Esc`.

## 5. Как всё проверяется и тестируется

```
npm install     # ставит jsdom (единственная dev-зависимость)
npm test        # node --test "test/*.test.js" — 72 теста
```

Используется встроенный в Node запуск тестов; тестовый фреймворк не нужен.

| Файл | Подход |
|---|---|
| `test/engine.test.js` | табличные проверки арифметики, приоритетов, процентов, факториала, констант, тригонометрии в градусах и радианах, логарифмов, НОД/НОК/nCr/nPr, статистики, матриц, форматирования; каждое сообщение об ошибке; проверка реестра (у каждой функции есть диапазон аргументов и реализация); **фаззинг** — 60 000 случайных строк должны дать число/матрицу или `CalcError`, но не другое исключение |
| `test/converters.test.js` | типовые перевода, крайние случаи температуры, полный перебор пар единиц каждой категории (конечные числа, A→B→A возвращает исходное), загрузка курсов с запасным адресом и ошибками, даты графика, параллельная история с кэшем и пропусками, формат денег — с поддельным `fetch` |
| `test/ui.test.js` | загружает настоящий `index.html` со всеми скриптами в **jsdom** (`test/helpers/dom.js` подставляет поддельные `fetch` и canvas) и управляет им как пользователь: каждая кнопка и набор Fn/Inv, случаи защиты ввода, история, точность, Deg/Rad, клавиатура, режимы, справка, величины, валюты онлайн/офлайн; а также **«обезьяна»** (6000 случайных нажатий и клавиш без единой ошибки страницы) и проверка «нет мёртвых кнопок» |
| `test/manual.test.js` | разбирает `docs/MANUAL.md`: примеры `` `выражение` → **результат** `` вычисляются движком, примеры «нажмите …» выполняются на настоящей странице, примеры `rad:` и `units:` используют свой режим; проверяет также, что упомянуты все функции движка и все кнопки интерфейса, а руководство ссылается только на существующие файлы и команды |

Следствие: если поведение функции изменилось, упадёт либо модульный тест, либо тест руководства — код, руководство и тесты не могут разойтись. CI (`.github/workflows/test.yml`) выполняет `npm install && npm test` на Node 22 при каждом push и pull request.

### Как добавить функцию

1. Добавьте запись в `FUNCTIONS` в `js/calc-engine.js` (и, если нужна кнопка, слот в `PAGES` в `js/app.js`).
2. Добавьте модульные тесты в `test/engine.test.js`.
3. Опишите её в `docs/MANUAL.md` с выполняемым примером `` `f(2)` → **4** ``; пока не описаны все функции, `test/manual.test.js` будет падать.

## 6. `variants/`

Прежние самостоятельные страницы (`calculatorEF.html` — основа текущей версии, `calculator-manual.html` — прежний мануал). В тестах не участвуют.
